# The first batch of the outside review, November 2026

An outside review of d07fe2b
([docs/MarketAgent_Review_and_Improvement_Plan.md](../../docs/MarketAgent_Review_and_Improvement_Plan.md))
put four fixes first. Each one was reproduced on that commit before it was
fixed:

- **A failed lookup read as "none".** A news search that failed returned
  `[]` and a calendar that failed returned no date, so
  `compute_attention(None, [], {}, None)` gave `quiet`, and the analysis
  and the brief saw an empty list with nothing to say it had failed.
- **A multiple the rewrite couldn't fix was shown anyway.** When the
  guard's rewrite call failed, came back empty or still had a multiple,
  the first text stood.
- **Discover's theme output was trusted.** A ticker that wasn't among the
  movers was shown, `"tickers": 42` raised, and `"tickers": "NVDA"` came out
  as N, V, D, A.
- **The analysis prompt said the abnormal move "isolates the reaction to
  the report".** Beta x SPY takes out the market's move, not sector news
  or other companies' reports that day.

## The change

- **Data states.** The news and calendar lookups raise when they fail. A
  row records what failed; its rank can be too low but never too high, so
  high and medium stand and quiet becomes `incomplete`. The analysis gets
  `unavailable` (from the `<key>_error` the stock page already recorded)
  and the brief gets it per name, each with a prompt paragraph: an empty
  value there means the lookup failed, not that there was nothing. The
  page says "couldn't be loaded" where it said "no headlines" or "not
  announced".
- **Multiples fallback.** If the rewrite fails, the first text loses its
  one sentence with a multiple, as long as two sentences are left. If it
  can't, the stock page shows the figures the analysis was written from,
  written in code; the brief keeps its first text.
- **Theme output** is checked field by field against the movers.
- **Earnings wording.** The analysis prompt calls the abnormal move the
  move around the report beyond the market, never the reaction to the
  report alone. The page's notes say the same.

The theme check and the multiples fallback are covered by the offline
tests: neither is something a model run measures. The fallback only acts
when a rewrite fails, so these runs will rarely see it.

Both prompts change. The analysis prompt changes for every stock page,
the earnings paragraph and the new `unavailable` paragraph alike. The
brief prompt gains one paragraph about a field that only appears when a
lookup failed.

Model: claude-sonnet-4-5 (`config.MODEL`). Budget: $8.

## Plan, written before any run

**New scenarios** (regression checks, in the train split):

- `news_unavailable` (analysis): STX falls 5.6% alone; its news lookup
  failed.
- `calendar_unavailable` (analysis): AVGO rises 1.5% with its theme; its
  calendar lookup failed. It also carries abnormal moves.
- `theme_name_data_failed` (brief): an AI compute theme falls together;
  STX, flat, had its news and calendar fail. Every other name reports in
  about a month, so "nothing reports this week" is only wrong because of
  STX.

Each records a failed lookup the way the app does, so one fixture serves
both sides: the analysis data carries an empty value beside a
`<key>_error`, which the code before this batch ignores; the brief's STX
row is ranked by whichever `compute_attention()` is checked out, so the
before side sees `quiet` with no reasons, as that app sent it. One
difference remains: `calendar_unavailable` has `events: {}`, as the stock
page now sets it, where the old code would have sent a dict of `None`s.
Both give `next_earnings_in_days: null`.

**New grading.** `theme_drop_before_earnings`,
`mixed_move_report_tomorrow` and `calendar_unavailable` gain a rubric rule
(e): fail an analysis that presents the abnormal move as the report's
effect alone. A regex also flags "isolat-". The three new scenarios each
have a rubric for their failed lookup and a regex for its usual wording
("no news", "no report scheduled"). The regexes catch candidates for
reading; whether a run fails is decided by reading it.

1. **A.** In at most 1 of the 48 after-fix runs of the two earnings

2. **B.** For each of `news_unavailable` and `calendar_unavailable`, at
   most 1 of the 24 after-fix runs turns the failed lookup into an

   both scenarios on both sides, not only the flagged ones.
3. **C.** In at most 1 of the 24 after-fix runs of
   `theme_name_data_failed` does the brief call STX newsless or quiet in a

4. **D.** The deterministic checks (forbidden phrasing, format,
   multiples, tickers mentioned) pass in every regression run. For each
   regression scenario, the judge passes at least the recorded rate times

**If the before side doesn't show the problem.** If the before runs of
a scenario in A, B or C don't show the failure their criterion counts,
that scenario didn't reproduce the problem and its after runs show only
that nothing got worse. That is recorded as such, not as an improvement.

**The judge is the model being graded.** Generation and judging use the
same model, so they can share a blind spot; judge stability checks narrow
that but can't remove it. That is why criteria 2 and 3 rest on reading
every run, and criterion 1 on reading every flagged one. The judge's pass
rates on A to C are recorded on both sides for information.
